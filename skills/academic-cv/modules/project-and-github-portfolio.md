# Project Analysis and GitHub Portfolio

## Project Intake

Collect, as applicable: - Project title and type. - Problem, objective,
and intended users/research question. - Project status and duration. -
Team size, user's role, and individual contribution. - Technologies,
tools, libraries, frameworks. - Dataset name, source, size, licensing,
classes, and split when relevant. - Methodology, model, architecture,
baseline, and experimental setup. - Metrics, actual results, evidence,
and limitations. - Demo, repository, report, or other links.

Adapt the form to ML/DL, software, hardware, research, or other project
types. Do not ask for accuracy where it is irrelevant.

## Evidence Rules

Do not invent model names, dataset details, sample counts, metrics,
results, features, or personal contribution. If information is absent,
ask or mark it incomplete.

## GitHub Audit

GitHub is optional unless the opportunity explicitly requires it. When
useful: 1. Request the profile or repository URL. 2. Confirm whether the
repository is public or the user can provide authorized access/files. 3.
Inspect README, directory structure, code organization, dependencies,
setup, dataset documentation, methodology, results, reproducibility,
license, and citation information. 4. Report strengths, issues, and
prioritized recommendations. 5. Research well-documented public
repositories in the same domain when this adds value. Learn from
structure and conventions; do not copy content or imply endorsement. 6.
Generate an original README based only on verified project facts. 7. Use
placeholders or ask questions for unknown facts. 8. Ask permission
before modifying or pushing changes. Never claim a change succeeded
unless confirmed.

## Research README Outline

-   Title and concise summary.
-   Problem and motivation.
-   Objectives and contributions.
-   Dataset and access instructions.
-   Methodology and architecture.
-   Repository structure.
-   Environment and installation.
-   Training/inference instructions.
-   Evaluation protocol and verified results.
-   Reproducibility.
-   Limitations.
-   License and citation.
-   Acknowledgements/references where appropriate.

Omit sections that do not apply. Never fabricate results or dataset
access.
