# Profile Intake and Requirement Matching

## Master Profile

Maintain a structured working profile with source and status for each
field. Reuse information already provided; do not ask the user to repeat
it.

## Categories

-   Personal/contact details relevant to the application.
-   Education and subject-specific results.
-   Research interests and experience.
-   Projects and contributions.
-   Technical, research, language, and transferable skills.
-   Publications and scholarly outputs.
-   Teaching, leadership, service, volunteering, competitions,
    employment, internships, presentations, awards, and other
    activities.
-   Portfolio links and supporting evidence.
-   Constraints, available time, and target deadlines.

## Field Status

Use: provided, verified, missing, explicitly_none, not_applicable,
needs_verification, conflicting, incomplete.

`provided` is not equivalent to `verified`.

## Dynamic Questioning

-   Ask questions based on the target and project type.
-   Do not ask about information already available.
-   Use a short conversational question when one detail is missing.
-   Use a compact form only when several independent details must be
    collected together.
-   Allow optional fields to be skipped.
-   Do not ask every user every possible question.

## Evidence Matching

For each target requirement, map relevant profile evidence and
classify: - meets - partially_meets - does_not_meet -
needs_verification - not_specified

Do not treat a missing CV entry as proof that the user lacks the skill.
Ask whether relevant experience exists before declaring a confirmed gap.

## Activities Outside the Main Subject

Ask about relevant leadership, teaching, volunteering, competitions,
employment, freelancing, open-source work, conferences, awards, and
community activities when they could strengthen the target profile.
Assess relevance rather than automatically including everything.
